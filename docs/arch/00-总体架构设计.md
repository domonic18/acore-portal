## 1. 技术选型（结论）

**Next.js 全栈单体**——6K 用户规模，单体优先，不引入微服务。

| 层 | 选型 | 结论要点 |
|---|---|---|
| 前端 | React 18 + Next.js App Router + Tailwind | 官网/论坛/商店/用户中心/后台统一在一个应用 |
| 后端 | Next.js Route Handlers（**不引入 NestJS**） | 后台复杂度未达独立服务阈值；单体优先是宪法 VII 硬边界 |
| ORM | Prisma **多 schema · 5 个 client** | 业务库可写迁移；游戏三库只读；auth 库契约写 |
| 缓存 / 会话 | Redis 7（session + 限速 + 热点缓存） | 会话 = JWT HttpOnly Cookie + Redis |
| 游戏命令层 | node-soap（worldserver 命令） | 超时 + 重试 + 幂等键回放 + 审计日志 |
| 邮件 | nodemailer + SMTP | 模板化；发信经 `mail-outbox` 队列 |
| 人机验证 | 腾讯云验证码 TCaptcha | 由 Cloudflare Turnstile 替换（国内可达性） |
| 图片 | 腾讯云 COS + CDN | 存量 4.4G 迁入 + URL 重写表 |
| 部署 | 腾讯云 CVM + docker compose + Caddy | 沿用现行生产套路；**人工发布**（见 §4） |

**选型变更记录**：research/01 §7 中「或 NestJS 独立服务」的备选**已否决**——理由是运营后台未达独立服务阈值，
拆分将违反宪法 VII（单体优先 / YAGNI）。其余各层与 §7 推荐一致。

## 2. 系统拓扑

```
                        ┌──────────── 浏览器 ────────────┐
                        │  门户 Next.js 应用             │
                        │  ├ 工具页 iframe ─────────────┼──→ 子站 rank.lokta.cn（独立应用/独立发布形态）
                        │  └ 第三方工具站 iframe ────────┼──→ webdkp.nfuwow.com 等
                        └───────────────────────────────┘
                                   │ HTTPS
                        ┌──────────▼──────────┐
                        │  Caddy（边缘）       │  TLS 终止 / 反代 / 安全响应头
                        │  域名前无 CDN/WAF    │  （腾讯云 CVM 直连）
                        └──────────┬──────────┘
                                   │
                        ┌──────────▼──────────┐
                        │  web（Next.js）      │  app → server → lib → constants
                        │  ├ middleware（edge）│  旧 URL 兼容 + 会话浅校验 + 角色校验
                        │  ├ RSC 页面          │  数据经 services/<域>/ 的 view 函数
                        │  └ Route Handlers    │  仅校验 / 会话 / 编排
                        └──┬────┬────┬────┬────┘
              ┌────────────┘    │    │    │    └──────────────┐
              ▼                 ▼    │    ▼                   ▼
      ┌───────────────┐  ┌─────────┐ │  ┌────────┐   ┌──────────────┐
      │ 业务库 acore_ │  │ Redis 7 │ │  │  SMTP  │   │  腾讯云 COS   │
      │ portal        │  │ session │ │  │  发信   │   │  + CDN       │
      │ (唯一可 DDL)   │  │ 限速    │ │  └────────┘   └──────────────┘
      └───────────────┘  └─────────┘ │
                                     │
        ┌────────────────────────────▼─────────────────────────────┐
        │ 游戏四库（AzerothCore 拥有 schema，本项目零 DDL）           │
        │  acore_auth    ← 契约写：仅 account 表 INSERT/UPDATE       │
        │  acore_characters / acore_world / acore_eluna ← 只读       │
        └───────────────────────────────────────────────────────────┘

        ┌───────────────────────────────────────────────────────────┐
        │ 外部通道（均走 lib/config.ts 收口的超时/重试/审计）          │
        │  SOAP worldserver（发货命令） · 腾讯云验证码 TCaptcha      │
        └───────────────────────────────────────────────────────────┘
```

### 2.1 数据存储职责边界（宪法 V）

| 库 | 写权限 | 约束 |
|---|---|---|
| 业务库 `acore_portal` | 本项目**可写**，Prisma migrations 是唯一 schema 真相源 | forward-only；合并后禁止修改；破坏性变更走 expand-contract 分批 |
| 游戏库 `acore_auth` | **仅 `account` 表**契约写（注册 INSERT / 改密 UPDATE） | 禁任何 DDL；写权限根本防线是 MySQL 账号权限 |
| `acore_characters` / `acore_world` / `acore_eluna` | **只读** | 禁任何 DDL；client 惰性建连，改连接需重启 |

### 2.2 关键数据流

**注册 / 登录**（宪法 I、IV：账号一致性 + 无感迁移）

```
浏览器 → Caddy → Route Handler（Zod 校验 + 媒体类型闸 + 同源闸）
   → services/auth
      ├─ 站点库：user 表（双格式哈希分派校验；$P$ 通过后立即重哈希为 $wp$ bcrypt）
      └─ 游戏 auth 库：account 表（契约写，与站点库双写，单边写即事故级缺陷）
   → 签发 JWT HttpOnly Cookie + Redis 会话
```

**下单 → SOAP 发货**（宪法 II：发货必须可靠可见）

```
支付成功 → 扣积分（流水实时更新余额）
        → services/orders 状态机 pending → paid → delivering
        → server/soap 执行发货（超时 + 重试 + 幂等键回放）
        → completed            ← 成功
        → delivery_failed(+重试队列 + 告警 + 人工补发入口)   ← 失败，**禁止静默**
```

**积分账本**（宪法 III）：余额 = 流水推导，余额表仅为加速读取的缓存；日终对账任务差异可见、可清零。

## 3. 目录与依赖方向

```
app  →  server  →  lib  →  constants
components  →  lib
```

- **单向强制**：禁止反向 import、禁止循环依赖；客户端组件禁止 import `server/`（`server-only` 包强制）。
- **app 层禁直连 prisma**：RSC 页面与 Route Handler 只做校验 / 会话 / 编排，取数经 `services/<域>/`；
  `grep -rn 'from "@/lib/db"' src/app` 应为空。
- **services 分域**：`services/` 根目录禁新增平文件，新域一律 `services/<域>/`；
  跨域基础服务只入 `services/shared/`（审计、限速、积分账本、发信队列等 13 项）；
  域间横向 import 由 `eslint-plugin-boundaries` 机械拦截（未登记的编排边直接 lint 失败）。
- **常量分层**：业务枚举（订单状态 / 积分流水类型 / SKU 路由键 / SOAP 命令名）一律进 `src/constants/`。
- **components 准入**：`components/ui/` 只收 ≥2 个消费者的通用组件；页面私有组件与 page 同目录。

## 4. 部署架构

### 4.1 生产形态

腾讯云 **CVM + Docker Compose**（`docker/docker-compose.prod.yml`），与 dev/test 三套 compose **完全独立**：

| 服务 | 职责 | 对外暴露 |
|---|---|---|
| `caddy` | TLS 终止、反代、安全响应头 | 80 / 443 |
| `web` | Next.js 应用 | 仅 `127.0.0.1:3000`（运维直连排查口，不经 TLS；公网入口只有 caddy） |
| `mysql` | 业务库 | **不发布端口**（迁移走容器网络内一次性服务，备份走 `docker exec`） |
| `redis` | 会话 / 限速 | **不发布端口** |
| `migrate` | 一次性 `prisma migrate deploy` | `--profile migrate` 才启动 |

- 生产栈**不含任何测试替身**（mailpit / soap-mock / initdb 一律不进生产）。
- 域名前**无 CDN / WAF**（腾讯云 CVM 直连 Caddy）——影响可信代理跳数配置 `security.trustedProxyHops`=1。
- **配置分域**（宪法 VI）：引导级凭据（业务库 / Redis 连接串、`SESSION_SECRET`）在宿主机 `.env.prod`（不入库）；
  游戏四库连接串与业务通道配置（SMTP / SOAP / 站点地址 / TCaptcha / COS）存业务库 `system_config` 表，经 `lib/config.ts` 收口。

### 4.2 发布方式

**当前为人工发布**（详见 [ops/production-deploy.md](../ops/production-deploy.md) §7）：

```bash
git fetch --all && git checkout <发布提交>
docker compose --env-file .env.prod -f docker/docker-compose.prod.yml up -d --build
docker compose --env-file .env.prod -f docker/docker-compose.prod.yml --profile migrate run --rm migrate
```

**顺序不可反**：新镜像引入的 schema 变更靠最后那条一次性 `migrate` 补上，漏跑则新代码读不到新列。

**尚未实施**：流水线自动发布。方案稿见 [plan/ci-deploy-pipeline-plan.md](../plan/ci-deploy-pipeline-plan.md)（方案告知稿，未实施）。

### 4.3 备份与恢复

cron `mysqldump` + 对象存储；恢复口径见 [ops/backup-restore.md](../ops/backup-restore.md)。
发布前后需与备份窗口对齐。

## 5. 边界与红线

| 边界 | 规则 |
|---|---|
| 生产主机 | 正在运行；一切备份 / 分析访问**只读**；切换下线前旧 WordPress 仓库保留勿动 |
| 旧 WordPress 仓库 | 切换下线前勿动 |
| 旧 URL 兼容 | `?p=` / `?page_id=` / `/wp-login.php` 等必须 301/302 到新路由（教程页截图与外部引用硬编码旧路径） |
| 子站 | `rank.lokta.cn` 是**独立仓库、独立发布形态**（腾讯云 SCF 容器镜像函数），与门户的 Compose 形态不同，不互相套用 |
| 凭据 | 禁止打印 / 落日志 / 入文档 / 入镜像；日志记事件不记敏感值 |
