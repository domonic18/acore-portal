## 里程碑说明

### M5 安全加固：撞库事故响应

- 目标: 撞库（凭据填充）事故的系统性加固——止血（审计可观测 / 人机校验失败关闭 / 边缘安全头）、认证面收敛（可信客户端 IP、限速锁、密码策略加固、时序枚举闭合）、事后可复盘（审计读取 + 安全看板 + 告警）
- 验收标准: **被撞账号可界定（审计含 IP 列且可检索）+ 撞库压测下全站可用性无劣化 + 登录面全档限速与锁定生效**
- 状态: **已上线** — 主体开发完成并已随生产栈发布；残余人工项（TOP-N 强制改密、SC-001 玩家真实登录）经用户裁决放弃

### M1 地基：账号全链路 + 游戏集成 + 路由兼容

- 目标: 注册 / 登录 / 找回改密（双写游戏库）/ 用户中心 / 游戏四库直连 / SOAP 命令层 / 301 路由兼容层 / 积分账本最小集
- 验收标准: **存量老用户真实登录成功率 100%（无感）**
- 状态: **已上线** — 开发完成并通过生产切换；SC-001 玩家真实登录验收经用户裁决放弃

### M2 营收：积分体系 + 商城全链路 + 后台最小集

- 目标: 积分账本（余额 + 流水 + 对账）/ 商品与分类（SKU 校验）/ 购物车 / 结账与 SOAP 发货闭环 / 服务类处理器 / 后台最小集 / 商城存量迁移
- 验收标准: **测试订单全链路（下单→扣分→发货→completed）+ 积分对账差异清零**
- 状态: **已上线** — 开发完成并通过生产切换；发货真机抽测通过

### M3 社区：论坛 + 内容资讯 + 全局框架

- 目标: 5 版块论坛（发帖 / 回帖 / 传图已开放）/ 存量论坛与文章迁移 / 公告与资讯归档 / 渐进计划时间轴 / 静态页后台可编辑 / 侧栏组件系统 / 首页四区块聚合
- 验收标准: **存量论坛与文章可访问，旧 URL 301 全部生效**
- 状态: **已上线** — 开发完成并通过生产切换

### M4 完善：工具页 + 通知 + 安全横切 + 统计运维

- 目标: rank / DKP 工具页 + 通知中心 + 积分通知 + 人机校验与登录限速 + 统计看板 + 系统设置 + 服务器 cron 备份 + SEO
- 验收标准: **新旧并行观察 1 周（读新写旧）→ 切换上线**
- 状态: **已上线** — 开发完成并通过生产切换

### M6 运营提效：商品运营 MCP

- 目标: 把后台商品与论坛管理能力以 MCP 协议对外暴露，供 Claude Code 等客户端调用，取代逐个填表单
- 验收标准: **令牌鉴权生效（无令牌 401）+ 白名单工具全量可用（tools/list 恒 12 个）+ 每次调用可审计（只记工具名/目标 id/成败/耗时）+ 与后台表单同校验 + 限速与日配额生效**
- 状态: **已上线** — 规格 §17；生产已配置令牌并联调通过；工具集恒 12 个（商品 7 + 论坛 5），商品域无删除入口，论坛「下架」为可逆软删
- 依赖: 无

### M8 发现：站内搜索

- 目标: 跨类型检索（资讯 / 攻略 / 帖子 / 商品 / 静态页·FAQ / 聚合条目）+ 分组结果页 + 统一检索底座
- 验收标准: **各内容类型均可检索且归入对应分组 + 仅正文出现的词也能命中 + 分组结果页可筛选分页 + 语义层不可用时降级为词项检索**
- 状态: **M8-a 已上线；M8-b 搁置** — M8-a（统一检索 service + 分组结果页 + 检索工具 + 四类内容）已随二期上线并被 M9 与 M6 共用；M8-b（接入聚合条目第五类及其向量化）随 M7 搁置
- 依赖: M8-a 零依赖；M8-b 待 M7 条目模型落地
- 边界: M8 只交付**检索底座 + 结果页 + 检索工具**；对话入口、会话历史、配额与降级编排归 M9

### M9 AI 助手：站内智能问答

- 目标: 对话入口 + 站内知识检索 + LLM 通道配置（对话与 embedding 双角色）+ 降级与配额
- 验收标准: **回答必附来源链接 + 检索不到时明说而非编造 + 通道故障自动降级 + 日配额生效 + 双协议可配**
- 状态: **已上线** — 规格 §20；生产已配置对话与 embedding 通道并完成真问验证；会话数据保留期与清理口径见 AGENTS.md 规则 34
- 依赖: M8-a（知识源为站内教程 / 静态页 / 商品 FAQ / 论坛精选帖，**不含聚合条目** ⇒ M7 不是其前置）

### M7 内容聚合：资讯与视频信息流

- 目标: 外部游戏资讯与视频源采集管道 + 聚合条目模型 + 资讯页升级为信息流 + 后台源管理
- 验收标准: **至少 2 个源稳定产出条目 + 去重零重复 + 前台信息流可按来源/类型筛选 + 抓取失败有重试与告警 + robots 检查真实生效 + 不落播放地址与本体**
- 状态: **搁置**（2026-11-19 用户决策：采集功能暂缓）— 规格 §18 保留，恢复时按 a/b 两段交付（a 段 RSS 与公开 API 源，b 段短视频签名网关 sidecar）
- 依赖: 无；其下游 M8-b 同步搁置

### N1 招募队友：RAF 招募进度（下一迭代主功能）

- 目标: 用户中心 RAF 招募从静态展示页升级为真实数据页——展示角色当前招募进度（已招募人数 / 招募目标 / 状态），并与游戏端 Eluna 脚本产生的数据联动
- 验收标准: **RAF 页展示真实招募数据（非硬编码零值）+ 角色维度隔离（只展示当前角色）+ 游戏端脚本未产出数据时明确空态而非报错 + 依赖的 eluna 库缺失不拖垮门户（该库缺失时整页降级而非启动自检失败）**
- 状态: **未开始** — 2026-11-19 用户指定为下一迭代主功能；游戏端 Eluna 脚本为本里程碑前置（脚本落地前先定数据契约：表结构、写入方、字段口径）；门户侧 eluna 空库的权宜处置与根因修法（`gamedb.eluna` 改可选、自检跳过缺失库）在本里程碑内一并收口
- 依赖: 游戏端 Eluna 脚本落地 + `gamedb.eluna` 可选化改造
- 现状: 页面框架已就绪（`/account/raf`，空态），数据接口契约 `GET /api/account/raf` 未接

## 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| deepagents 上游版本 churn | 打断检索与助手编排 | 锁版本；编排层薄封装在检索服务内；退路 = LangGraph 原生 StateGraph（规格 §19.4） |
| embedding 供应商可达性与成本 | 语义层不可用或成本失控 | 语义层不可用即整体降级为词项检索；通道可后台切换；向量存 MySQL，不引入新组件 |
| agent 多步 token 放大 | 单次问答成本超预期 | 步数与 token 预算闸 + 日配额（规格 §19.6 / §20.3 同一套） |
| 语料增长致向量召回退化 | 检索精度下降 | 5 万条阈值重评向量库方案（规格 §19.5 已定）；进程内索引增量更新 |
| 检索口径双写漂移 | 结果页 / 助手 / MCP 三处不一致 | 统一检索 service 单源供给三处；`search_site` 工具与助手侧同一入口 |
| 采集源平台签名算法变更 | 短视频网关失效、条目停更 | 签名与采集解耦；失败重试 + 告警可见；RSS 与公开 API 源兜底（M7 恢复时适用） |
| 游戏端脚本未落地 | N1 无法交付 | 先定数据契约再动手；门户侧不因游戏端未就绪而阻塞其余功能 |
