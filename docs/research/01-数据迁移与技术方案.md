## 1. 现有架构速览

```
lokta.cn (WordPress, docker: nginx+php+mysql8+redis)  @101.42.117.123 /home/ubuntu/acore-cms/
  ├─ mycred(积分) + WooCommerce(商店,旧式posts订单) + bbPress(论坛) + 邀请码 + 21激活插件
  ├─ acore-wp-plugin ★ 直连游戏四库(Doctrine DBAL) + SOAP(worldserver)
  └─ iframe → rank.lokta.cn (独立应用 acore_armory 容器) / webdkp.nfuwow.com / nfuwow×3 / 虎牙·抖音
```

关键事实（迁移设计的前提）：
- 订单存储为 **WooCommerce 旧式 posts 模式**（`wp_posts.post_type=shop_order`，HPOS 表为空）
- 积分余额在 `wp_usermeta`（mycred_default / _total / _history），流水在 `wp_myCRED_log`
- 游戏库：`acore_auth` / `acore_characters` / `acore_world` / eluna（连接配置在 wp_options `acore_db_*`，凭据**不入库不入文档**，迁移时走环境变量）
- rank.lokta.cn 独立于 WP，不在迁移范围

## 3. 密码无感迁移（已定决策，用户登录体验零变化）

1. 新系统实现 **phpass（WP `$P$` 变体）校验器**（算法公开，Node 可自实现或用现成包）
2. 登录时序：查新哈希 → 无则 phpass 校验旧哈希 → **通过后立即 bcrypt/argon2 重哈希写回**（一人一次，透明）
3. 注册/改密/重置一律新算法 → 存量自然衰减
4. **双写约束**：改密/重置需同步游戏 auth 库（现状契约：站点与游戏同密）；是否解除同密（游戏端独立密码）是产品决策，**默认保持同密**
5. 兜底：phpass 校验异常的账号走邮箱重置路径
6. 验收：抽样 100 老账号旧密码登录成功 + 登录后哈希已更新

## 4. 订单状态清洗（待用户确认口径）

现状 1,897 笔订单：**1,895 笔滞留 processing**（发货后未自动完结的旧缺陷）、仅 2 笔 completed。

建议口径：**已发货即 completed**。判定依据（可执行）：
- 有对应 myCRED 扣分流水（woocommerce_payment）→ 视为已支付
- 有 SOAP 发货记录/订单 meta 发货标记 → completed
- 两者俱全但积分扣减与订单金额不符 → 单列 `review` 人工复核
- 无扣分流水 → `cancelled/pending` 视旧单性质

新系统状态机修复点：支付成功→扣分→发货成功→**自动 completed**；发货失败→`delivery_failed`+重试队列+人工补发入口。

## 5. 积分对账（迁移必做）

1. 按 `wp_myCRED_log` 全量流水重算每用户余额
2. 与 `wp_usermeta.mycred_default` 存量余额逐户比对
3. 差异清单人工确认后以**流水重算值为准**（或以存量为准，二选一后固化）
4. 迁移后新系统开启"每笔流水实时更新余额+日终对账任务"双保险
5. 验收：差异清单清零 + 抽样 20 户余额与新系统前端展示一致

## 6. 统计数据决策点

- 文章阅读数（wp_post_views）：**必迁**（前端展示依赖）
- WP Statistics 访客数据（28.9 万 UV/80 万 PV）：二选一
  - a) 自建埋点（保留累积历史，需迁 46 万+ 行）
  - b) 历史数据归档不迁，新系统接 Umami/Plausible（轻量省事）
  - 倾向 b + 阅读数自建；**待用户确认**

## 7. 技术栈建议

**推荐：Next.js 全栈单体**（6K 用户规模无需微服务）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 18 + Next.js App Router + Tailwind | 官网/论坛/商店/用户中心统一 |
| 后端 | Next.js Route Handlers（或 NestJS 独立服务，若运营后台变重） | 单体优先 |
| ORM | Prisma | 新业务库 + 游戏三库只读连接 + auth 库可写 |
| SOAP | node-soap 封装命令层 | 超时/重试/幂等/审计日志 |
| 会话 | JWT HttpOnly Cookie + Redis | 记住登录=长 token + 轮换 |
| 缓存 | Redis | session/验证码限速/热点缓存 |
| 邮件 | nodemailer + SMTP（沿用现有发件账号） | 模板化 |
| 人机验证 | Cloudflare Turnstile | 登录/注册 |
| 图片 | 腾讯云 COS + CDN | 存量 4.4G 迁入 + URL 重写表 |
| 部署 | 现有轻量服务器 docker compose + caddy（与 invest 同套路） | 备份=cron mysqldump+rsync（本次备份即模板） |

## 8. 实施顺序（对齐规格 §16）

M1 账号+游戏集成+路由兼容（含密码无感）→ M2 积分+商城+后台最小集 → M3 论坛+内容 → M4 工具页/搜索/通知/统计

里程碑验收锚点：
- M1 末：100 老用户真实登录成功率 100%（无感）
- M2 末：测试订单全链路（下单→扣分→SOAP 发货→completed）+ 对账通过
- M3 末：存量论坛/文章可访问、旧 URL 301 生效
- 上线：新旧并行观察 1 周（读新写旧）→ 切换

## 9. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| phpass 兼容遗漏（极老哈希格式） | 中 | 兜底邮箱重置；灰度期客服口径 |

| rank 子域服务耦合 | 低 | iframe 原样保留，解耦后置 |
