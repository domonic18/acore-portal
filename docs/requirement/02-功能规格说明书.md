# 01 功能规格说明书（Lokta 官网重开发）

- 版本: v3（2026-10-23 定稿，合并早期两份分析报告，唯一权威需求基准）
- 依据: 生产 WordPress 系统全量备份逐项核对（备份位于 `~/Code/lokta/`）
- 约定: 每项功能标注优先级——**P0** 首版必须 / **P1** 首版应有 / **P2** 可后延；"现状"指线上 WordPress 真实行为，移植时不得无声变更

## 1. 系统概述

**老克塔（lokta.cn）**：魔兽世界 60 年代怀旧服（AzerothCore 引擎）社区门户，"怀旧公益项目"。系统承担四类职责：

1. 社区门户：资讯、教程、论坛、直播入口
2. 游戏数据服务：排行榜/在线玩家/地图/封号记录（iframe 嵌入独立子域）
3. 玩家自助服务：注册开号、角色查询、物品恢复
4. 虚拟商品商城：积分+真实货币双通道，游戏内自动发货

**三条铁律**（贯穿所有模块的设计约束）：
- 站点用户名 = 游戏账号名，注册即同步写入游戏 auth 库（单向站点→游戏）
- 一切涉及密码/账号的变更必须双写（WP 侧 + 游戏 auth 库）
- 商品 SKU `itemsend_{游戏物品ID}` 是商城与游戏世界的映射契约

术语表：积分（站内虚拟货币，源 mycred）· 角色（游戏内人物，GUID 标识）· 发货（SOAP 邮件投递游戏物品）· 服务类商品（改名/转阵营等，无实体物品）· 邀请码（注册凭证）

## 3. 账号体系

### 3.1 注册（P0）
| 功能点 | 现状行为（必须保持） |

## 5. 商城（P0，营收核心）

### 5.1 商品模型
- 99 个在售商品，14 分类：坐骑31/传家宝28/幻化24/武器14/物理系10/锁甲6/皮甲6/服务5/板甲4/法术系4/饰品3/布甲3/消耗品2/容器1
- 两类商品：**物品类**（SKU=`itemsend_{游戏物品ID}`，发货走 SOAP 邮件）与**服务类**（独立 SKU 作处理器路由键，如 `item-restoration`/`char-change-race`/`char-change-faction`/`char-change-customize`/`char-change-name`，发货走 SOAP 命令处理器；2026-10-23 按备份库勘误，原述"服务类无 SKU"有误）
- 无全局属性筛选（未建 pa_ 属性），分类即筛选维度
- 价格区间 10~238（语义=积分）

### 5.2 商品列表 `/shop`
分类筛选 + 价格排序 + 分页 + 全局搜索可达（§10）；商品卡片：图/名/价/分类

### 5.3 商品详情
图集、描述、价格、分类归属；**Wowhead 物品浮窗**（武器/物品类）；加购；未登录引导登录

### 5.4 购物车 `/cart`
数量/小计/移除/**积分券抵扣**入口；侧栏"最近浏览"联动；**行内展示下单参数**（角色名/所选恢复物品/目标账号等）供用户复核

### 5.5 结账与发货 `/checkout`（本系统最核心链路）
1. **禁止游客结账**（强制登录；结账页登录提醒开启）
2. **动态角色选择**：下单必须选择名下游戏角色，服务端校验角色归属（防越权下单他人角色）
3. 支付方式：积分支付（主用，余额不足拦截）+ 真实货币网关预留（现状配置过 PayPal 全栈/线下转账/bacs/cheque/cod 顺序）
4. 支付成功链路：**扣积分（写流水）→ SOAP 邮件发货 → 订单状态推进**；失败需重试与人工补发
5. ⚠️ 现状缺陷：发货后订单停留 processing（1,895/1,897）——新系统状态机必须闭环（02 §4）

### 5.6 服务类商品处理器（9+ 种，逐一还原）
改名 · 改阵营 · 改种族 · 改外观(幻化单件/套装) · 装备/物品恢复 · 角色转移 · 角色复制 · 公会变更 · 名字解锁——建议策略模式：每类一个 SOAP 命令处理器 + 前置校验

**下单输入字段矩阵**（2026-10-23 按插件源码核实，各商品在商品页采集、购物车行携带、订单行 meta 落库、发货时读取）：

| SKU/处理器 | 下单输入 | 服务端校验 |
|---|---|---|
| itemsend_* 物品类 / 幻化单件 / 幻化套装 / 改种族 / 改阵营 / 外观重置 | 角色选择（名下角色下拉） | 角色归属 |
| item-restoration 装备恢复 | 角色选择 + **可恢复物品单选**：选角色后 REST 异步加载该角色可恢复列表，Wowhead 浮窗展示物品名/图标，单选；与用户中心物品恢复同源 | 支付前校验服务器在线；未选物品不得加购 |
| char-transfer 角色转移 | 角色选择 + 目标账号名 | 账号存在性 |
| guild-change 公会变更 | 角色选择 + 新公会名 | 公会名合法性 |
| name-unlock 名字解锁 | 角色选择 + 解锁名（首字母大写规范化） | 名字合法性/占用 |

下单参数随单落订单行 meta（`acore_char_sel`/`acore_restore_item_sel`/`acore_dest_account` 等），发货处理器读取执行。

> ⚠️ 决策 D6：现状订单行存在 `acore_msg_dest`（物品类可指定收件角色、寄给他人）能力，**新系统不移植**（2026-10-23 用户决策）——物品一律寄给下单所选角色。

| 权限 | 默认 subscriber；内容限制功能未实质使用 | RBAC 简化为：游客/用户/版主/管理员 |
| 合规 | 用户协议/和谐公约页 | 保留页面 |
| 性能 | 无页面缓存/对象缓存（Redis 属游戏栈） | 静态化/缓存策略自定，非硬性移植项 |
