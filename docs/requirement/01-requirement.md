## 1. 项目定位

老克塔（lokta.cn）官网重开发：魔兽世界 60 年代怀旧服（AzerothCore 引擎）社区门户，"怀旧公益项目"。替代生产 WordPress 系统（PHP 已过时，旧仓库 `~/Code/acore-cms` 保留至切换下线）。

**目标用户**: 站内 6,330 注册玩家（站点账号=游戏账号）；游客（经邀请码注册的新玩家）

**核心价值**: 四类职责一体——① 社区门户（资讯/教程/论坛/直播）② 游戏数据服务（排行榜/在线玩家/封号记录）③ 玩家自助服务（注册开号/角色查询/物品恢复）④ 虚拟商品商城（积分支付+SOAP 游戏内自动发货）。与游戏世界（四库直连+SOAP 命令通道）的深度集成是外部替代品不具备的。

**三条铁律**（贯穿所有模块）:
1. 站点用户名 = 游戏账号名，注册即同步写入游戏 auth 库（单向 站点→游戏）
2. 一切涉及密码/账号的变更必须双写（站点 + 游戏 auth 库）
3. 商品 SKU `itemsend_{游戏物品ID}` 是商城与游戏世界的映射契约

## 2. 分期功能范围

## 3. 明确不做清单

- **物品类商品寄送他人角色**（现状 acore_msg_dest 能力）——D6 决策（2026-10-23）：物品一律寄下单所选角色
- **微服务架构**——6K 用户规模，单体优先
- **页面构建器**（Elementor 式）——内容一律 Markdown/MDX，仅 2 页在用且直接转换
- **pmpro 订阅体系**——现状休眠（未安装），数据归档不迁
- **站点与游戏密码解除同密**——D2 默认保持同密契约（可复议）
- **多语言**——现状单语言，无此需求

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| 兼容 | 老用户登录体验零变化（phpass 透明升级，M1 验收=100 老账号真实登录成功率 100%） |
| 安全 | Cloudflare Turnstile（登录/注册）+ 登录限速 + 会话安全；游戏库凭据仅环境变量 |
| SEO | 语义化 URL + 301 兼容层全覆盖（旧 URL 有外部/教程硬编码引用）+ sitemap |
| 备份 | 服务器 cron mysqldump + rsync/对象存储（对齐本次备份流程，research/01 §7） |
| 性能 | 6K 用户规模；静态化/缓存策略自定，非硬性移植项 |
| 可靠 | SOAP 发货失败必须可见：重试队列 + 告警 + 人工补发入口（现状 1,895 单静默滞留是反面教材） |

## 5. 验收标准

- 每里程碑验收锚点见 [plan/development-plan.md](../plan/development-plan.md)，均为可执行可验证条目
- M1：100 老用户真实登录成功率 100%（无感）
- M2：测试订单全链路（下单→扣分→SOAP 发货→completed）+ 积分对账差异清零
- M3：存量论坛/文章可访问，旧 URL 301 全部生效
- 上线：新旧并行观察 1 周（读新写旧）→ 切换
